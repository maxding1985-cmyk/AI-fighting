# AI Tank Duel MVP

一个“赛前用自然语言生成策略规则、开战后由服务端驱动坦克自动对战”的双人原型游戏。

玩家不直接操作坦克，而是在开战前描述战术，例如“随机运动，一直开炮，遇到子弹躲避”。系统会把战术编译成 JSON 规则；战斗开始后，服务端按规则逐 tick 执行移动、转向、射击和躲避。

## 当前状态

当前版本已经从单机原型升级为可局域网双人测试的服务端权威 MVP：

- 支持创建房间、加入房间、复制邀请链接。
- 支持两名玩家在不同浏览器或不同设备上进入同一房间。
- 支持服务端权威战斗循环，客户端通过 SSE 同步状态。
- 支持自然语言生成策略规则，并在开战前确认锁定。
- 支持本地生成器、玩家自带 AI、服务端默认 AI 三种生成方式。
- 支持退出游戏流程：单人或对手离线可直接退出，双方在线时需要另一方确认。
- 支持基础断线恢复、刷新恢复玩家身份、战斗日志和决策日志。
- 当前仍定位为 MVP/局域网测试版本，尚未做公网部署安全加固。

## 已实现功能

### 战斗系统

- Canvas 像素风坦克战斗画面。
- 服务端权威战斗引擎。
- 双坦克自动对战。
- 子弹、射击冷却、障碍物、命中判定、超时平局。
- JSON 规则校验与解释执行。
- 决策日志：展示每 tick 匹配的规则、执行动作，以及射击/移动被跳过的原因。
- 针对“随机运动 / 一直开炮 / 遇到子弹躲避”等复合意图优化了本地策略生成。

### 房间与联机

- 创建房间、加入房间。
- 房间码邀请链接：`?room=房间码` 可直接预填加入。
- 双浏览器 / 双设备通过 SSE 同步同一场战斗。
- SSE 心跳、断线宽限、自动重连和快照恢复。
- 同一标签页刷新后自动恢复玩家身份。
- 其他标签页可手动恢复上次身份。
- 再来一局重置流程。
- 房间自动清理：
  - 所有玩家离线且 30 分钟无活动后自动清理。
  - 已退出房间默认 5 分钟后自动清理。
- 退出游戏流程：
  - 只有一名玩家时可直接退出。
  - 对手离线时可直接退出。
  - 双方在线时，一方请求退出，另一方确认后退出。

### AI 策略生成

页面中现在明确区分三种生成方式：

1. `本地生成器`
   - 不需要 API Key。
   - 速度快，适合本地测试。
   - 理解能力有限，但针对常见中文战术做了关键词优化。

2. `我的 AI`
   - 玩家填写自己的 OpenAI-compatible 配置。
   - 包括 `Base URL`、`Model`、`API Key`。
   - API Key 只保存在当前浏览器 sessionStorage。
   - 生成时发送给本机 Node 服务端，由服务端代调 `/chat/completions`。
   - 不会进入房间快照，也不会广播给对手。

3. `服务端 AI`
   - 使用服务器环境变量中的默认 AI 配置。
   - 适合房主统一配置模型，玩家无需填写 Key。

AI 生成逻辑已经调整为显式模式：

- 用户选“我的 AI”但未填写 API Key，会直接提示错误。
- 用户选“服务端 AI”但服务端未配置 Key，会直接提示错误。
- AI 调用失败或返回非法规则时，不再静默伪装成本地生成结果。
- 规则预览区会显示来源、模型和能力摘要，例如“会移动 / 会射击 / 会躲子弹”。

## 运行

### 本机运行

```bash
npm start
```

然后打开：

```txt
http://localhost:5173
```

### 局域网运行

如果需要让同一 Wi-Fi 下的另一台设备访问，请监听 `0.0.0.0`：

```bash
HOST=0.0.0.0 PORT=5173 npm start
```

查看本机局域网 IP：

```bash
ifconfig | grep "inet "
```

另一台设备访问：

```txt
http://你的局域网IP:5173
```

例如：

```txt
http://192.168.124.8:5173
```

注意：

- 两台设备需要在同一个局域网。
- macOS 防火墙弹窗需要允许 Node 接收连接。
- 浏览器代理/VPN 可能影响访问局域网地址。

## 接入真实 AI

### 使用“我的 AI”

在页面中选择 `我的 AI`，填写：

- `Base URL`：例如 `https://api.openai.com/v1`
- `Model`：例如 `gpt-4.1-mini`
- `API Key`：你的 API Key

然后输入战术并点击“调用我的 AI 生成”。

示例战术：

```txt
随机运动，一直开炮，遇到子弹躲避
```

生成后请检查规则预览中的：

- 来源是否为“我的 AI”。
- 模型名是否正确。
- 能力摘要是否包含期望动作，例如“会移动 / 会射击 / 会躲子弹”。
- 规则列表是否符合预期。

确认无误后，点击“确认规则并准备”。

### 使用“服务端 AI”

可以用环境变量配置服务端默认 AI：

```bash
AI_RULES_API_KEY="你的 API Key" \
AI_RULES_MODEL="你的模型名" \
npm start
```

可选配置：

```bash
AI_RULES_BASE_URL="https://api.openai.com/v1"  # 默认值
AI_RULES_TIMEOUT_MS=12000                     # 默认 12 秒
AI_RULES_FORCE_LOCAL=true                     # 强制使用本地生成器
```

配置后，页面选择 `服务端 AI` 即可使用默认模型生成规则。

## 房间清理配置

房间状态仍然保存在内存中，但服务端会自动清理过期房间，避免长时间局域网试玩时堆积无效房间。

默认值：

- 所有玩家离线且 30 分钟无活动后清理房间。
- 已退出房间 5 分钟后清理。
- 每 60 秒扫描一次。

可选环境变量：

```bash
ROOM_IDLE_TTL_MS=1800000          # 所有玩家离线后的房间保留时间，默认 30 分钟
CLOSED_ROOM_TTL_MS=300000        # 已退出房间保留时间，默认 5 分钟
ROOM_CLEANUP_INTERVAL_MS=60000   # 清理扫描间隔，默认 60 秒
```

## 测试

```bash
npm test
```

运行真实浏览器 UI E2E：

```bash
npm install
npx playwright install chromium
npm run test:ui
```

如果本地已经安装过依赖和 Playwright Chromium，之后只需要运行 `npm run test:ui`。

当前测试覆盖：

- 战斗引擎基础行为。
- 规则校验。
- 本地策略生成。
- AI 生成器成功、失败和显式模式行为。
- 房间创建、加入、恢复。
- 房间自动清理和已关闭房间过期。
- 服务端权威战斗流程。
- HTTP API 端到端流程：创建房间、加入、生成规则、确认开战，并验证玩家 A 会移动和开炮。
- 浏览器 UI 端到端流程：两个独立浏览器会话创建/加入房间、生成/确认规则、开战、验证玩家 A 移动/开炮，并覆盖双人在线退出确认。
- 断线宽限和重连状态。
- 退出游戏请求和确认流程。

### 自动测试

- GitHub Actions 会在 push 到 `main`、Pull Request 和手动触发时自动运行 `npm test` 和 `npm run test:ui`。
- 本地提交前可以安装 git hook：

```bash
npm run install-hooks
```

安装后，每次 `git commit` 前都会自动执行 `npm test`。如果测试失败，提交会被阻止。

注意：HTTP E2E 和浏览器 UI E2E 会启动本地服务并监听临时端口。如果当前沙盒或系统权限禁止监听端口，测试会自动跳过对应用例；在正常本地环境和 GitHub Actions 中会完整执行。

## 当前限制

- 房间和战斗状态只存在内存中，服务重启后会丢失。
- 房间清理只能释放内存房间，不能提供跨重启恢复。
- 当前适合本地或局域网可信环境测试，不建议直接公网暴露。
- 玩家自带 API Key 会发送到当前 Node 服务端代调 AI，公网部署前需要 HTTPS、权限控制和更严格的密钥保护。
- SSE 已能覆盖当前 MVP，但大规模或低延迟场景可能需要 WebSocket。
- 本地生成器仍是关键词/模板式生成，复杂策略需要真实 AI 才能更准确理解。
